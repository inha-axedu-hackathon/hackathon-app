# 징검돌 문제 만들기 (`/teacher/generate` 화면 + `POST /api/generate`)

2026-11-14 · 정환희 · 상태: **예비교사 흐름대로 구현**(14:00)

흐름(예비교사 11/14): **① 성취기준 → ② 대단원·소단원·차시 → ③ 서술형/서답형/선다형 → ④ 생성 → ⑤ 교사 검토 → ⑥ 징검다리**.
교사 화면 탭 옆 [＋ 징검돌 문제 만들기]에서 들어간다. AI 결과는 초안이고, 선생님이 고치고 뺀 뒤 [징검다리에 올리기]를 눌러야 저장된다(SPEC 6-1 사람 감독). 시연에서는 브라우저(`localStorage["jingum:generated"]`)에만 저장한다.

- 성취기준: 2022 개정 국어과 교육과정 중학교 [9국01]~[9국06] 51개(`data/curriculum/standards-9kuk.json`, 팀원 제공 PDF에서 옮김). 코드로 고르면 서버가 전문(+ [9국04-01] 해설)을 넣는다. 예시 기준은 PDF 58쪽 [9국04-01].
- 교과서 단원·차시: `data/curriculum/units.json`. **시연용 예시**라 실제 도입 때는 학교 교과서 목차로 바꾼다.
- 문항 유형: 선다형(돌마다 3문항: 2개 + 틀렸을 때 비슷한 문제), 서답형(2문항, 정답·허용 답), 서술형(1문항, 모범 답안·채점 요소 2~3개).

## 1. 부르는 법

```bash
curl -s http://localhost:3000/api/generate -H 'Content-Type: application/json' -d '{
  "codes": ["9국04-01"], "lessonId": "u4-2-2", "type": "choice", "count": 1
}'
```

| 입력 | 규칙 |
|---|---|
| `codes` | 성취기준 코드 1~3개, 목록에 있는 것만(대괄호 있어도 됨) |
| `lessonId` | `units.json`의 차시 id |
| `type` | `choice`(선다형) · `short`(서답형) · `essay`(서술형) |
| `count` | 만들 돌 개수 1~5(기본 3) |
| `memo` | 선택, 교사가 덧붙이는 말 500자까지 |
| `grade` | 선택, 기본 "중학교 2학년" |

실측(11/14, Haiku 5.5): 돌 1개 약 2,200토큰, 10~15초. 같은 입력은 저장본으로 0토큰.

응답(200) — 돌 모양은 `data/stones.json`의 돌과 같다(`components/student/stones.ts`의 `StoneCard`):

```json
{
  "draft": true,
  "needsTeacherReview": true,
  "stones": [{
    "id": "gen-1", "char": "ㄷ", "section": "가획", "kind": "card", "minutes": 2,
    "concepts": ["가획", "소리의 세기"],
    "card": "ㄷ은 ㄴ에 획을 하나 더해 만든 글자예요. 소리가 ㄴ보다 조금 세지기 때문에 획을 더했어요.",
    "questions": [
      { "id": "g1-1", "prompt": "…", "options": ["…", "…", "…"], "answer": 1, "explain": "…" },
      { "id": "g1-2", "…": "굳히기 2번" },
      { "id": "g1-3", "…": "틀렸을 때 푸는 비슷한 문제" }
    ]
  }],
  "dropped": 0,
  "usedLLM": true,
  "model": "claude-haiku-5-5",
  "tokens": { "used": 1487, "calls": 1 }
}
```

실패: 400(입력), 403(다른 사이트 요청, 또는 배포 주소에서 꺼져 있음), 413(요청이 큼), 429(10분에 10번 초과 또는 오늘 몫 소진), 502("초안을 만들지 못했어요": AI 답이 검사를 하나도 못 통과), 503(키 없음).

## 2. 안전장치

- **AI 원문은 돌려주지 않는다.** 검사를 통과한 값만 돌려준다. 선택지 3개(서로 다름, 각 60자), 정답 번호 0~2, 질문 120자, 해설 160자, 카드 200자, 구간은 상형·가획·병서·기타 중 하나. 하나라도 어긋난 돌은 버리고(`dropped`), 버린 까닭은 내용 없이 코드만 서버 로그에 남긴다.
- **배포 주소에서는 꺼 둔다**(`GENERATE_ENABLED=1`일 때만 열림). 교사 검토 화면이 생기면 교사 인증 뒤에만 연다.
- 다른 사이트 요청 403(`crossSite`), 요청 크기 12KB, 전체 10분에 10번(같은 입력은 저장된 답이라 세지 않음).
- 토큰: **따로 세는 몫** `LLM_GENERATE_TOKENS`(기본 20,000). 하루 상한 `LLM_DAILY_TOKENS`와 비상 스위치 `LLM_DISABLED=1`도 그대로 적용된다. 학생 채점(explain) 몫을 먹지 않는다.
- 입력의 메일·전화번호는 가리고 보낸다(`maskPII`). 학습 내용 안의 지시는 따르지 않게 지시문에 적었다.
- 모델은 다른 API와 같다: 안뇽GPT(BAZE 게이트웨이) `/claude/v1/messages` + `claude-haiku-5-5`, 생각 조금(effort low), 30초 상한. temperature는 넣지 않는다.

## 3. 비용 (측정)

- 돌 1개 = **약 1,500토큰**(입력 약 600 + 출력 약 900~1,600, 생각 포함), 약 8.5초. 같은 입력을 다시 보내면 0토큰(3시간 저장).
- 돌 3개는 약 3,000~4,000토큰으로 예상. 출력 상한은 돌 하나에 700(+생각 4,000), 최대 4,000.

## 4. 안뇽GPT를 써도 되나

된다. 지금 쓰는 게이트웨이(해커톤 크레딧)와 같은 경로라 새 키·새 업체가 없다. 선생님의 학습 내용·성취기준은 학생 개인정보가 아니라서 학생 글보다 부담이 적다. 다만 해커톤 크레딧이라 행사 뒤 실제 학교에서 쓰려면 데이터 보관·학습 사용 여부를 계약으로 확인해야 한다(SPEC 17장 멘토 질문 7).

## 5. 곧 구체화할 것 (팀 결정)

1. 성취기준 입력 방식: 코드 목록에서 고르기(예: `[9국04-02]`) vs 자유 입력
2. 돌 개수와 종류: 카드만 vs 실험실(`kind: "lab"`, 목표 글자) 연결까지
3. 교사 검토 화면: 어디에서(`/teacher/…`), 고치기·지우기·승인 버튼, 승인한 돌만 학생 경로에 들어가게
4. 오개념 연결: 오답 선택지를 `lib/content.ts`의 오개념 ID(M1~M7)와 묶을지
5. 저장: 승인한 돌을 어디에 둘지(지금은 저장하지 않음)
6. 다른 단원·교과로 넓힐 때 `section` 값을 어떻게 정할지(지금은 "기타")

검증: `npm run check:api`에 입력 검사 3개 + 다른 사이트 차단 1개, `AI=1`이면 실제 초안 1개 형식 검사가 들어 있다.
